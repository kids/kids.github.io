# 人物关系网络数据库构建与商业化业务计划

## 一、项目概述

### 1.1 项目定位
构建一个基于互联网数据的人物关系网络数据库，通过自动化数据抓取、智能消歧和画像构建，形成高质量的人物关系图谱，为商业应用提供数据服务。

### 1.2 核心价值
- **数据资产**: 构建持续更新的结构化人物关系数据资产
- **技术壁垒**: 基于搜索增强LLM的人名消歧和ID画像技术
- **商业价值**: 为BD、市场拓展、投资研究等场景提供数据支持

### 1.3 目标市场
- 投资机构（VC/PE）的投前研究和投后管理
- 企业BD和市场拓展团队
- 媒体和内容平台的推荐系统
- 政府机构和研究机构的网络分析

## 二、技术架构与实现路径

### 2.1 数据抓取层

#### 2.1.1 数据源规划
**公开数据源：**
- **新闻媒体**: 财经媒体、科技媒体、行业媒体（36氪、虎嗅、TechCrunch等）
- **社交媒体**: LinkedIn、Twitter/X、微博、脉脉等
- **企业公开信息**: 公司官网、招股书、年报、新闻稿
- **学术平台**: 知网、Google Scholar、ResearchGate
- **会议活动**: 行业会议、论坛、路演活动的公开信息
- **投资平台**: Crunchbase、企查查、天眼查等

**数据抓取策略：**
- 多源数据融合，提高数据覆盖度和准确性
- 增量更新机制，持续监控数据源变化
- 合规性保障，仅抓取公开信息，遵守robots.txt和API限制

#### 2.1.2 抓取技术栈
- **爬虫框架**: Scrapy、Playwright（处理动态内容）
- **数据存储**: 分布式存储系统（HDFS/S3）+ 图数据库（Neo4j/ArangoDB）
- **任务调度**: Airflow/Celery实现定时抓取和增量更新
- **反爬虫应对**: 代理池、请求频率控制、User-Agent轮换

### 2.2 数据处理层

#### 2.2.1 实体识别与抽取
**人物实体识别：**
- 使用NER模型（BERT/BiLSTM-CRF）识别文本中的人名
- 支持中英文人名识别
- 处理别名、昵称、英文名等变体

**关系抽取：**
- 基于规则的关系抽取（职位、投资、合作等）
- 基于BERT的关系抽取模型
- 事件抽取（融资、并购、合作等事件中的人物关系）

**关键信息抽取：**
- 职位信息（公司、职位、时间）
- 教育背景（学校、专业、学位）
- 投资关系（投资方、被投方、轮次、金额）
- 合作关系（合作伙伴、项目、时间）

#### 2.2.2 数据清洗与标准化
- 文本清洗（去除HTML标签、特殊字符）
- 时间标准化（统一时间格式）
- 公司名称标准化（处理简称、全称、英文名等）
- 职位标准化（统一职位层级和分类）

### 2.3 人名消歧与ID画像层（核心技术创新）

#### 2.3.1 人名消歧技术路径

**问题定义：**
- 同一人物在不同数据源中可能有不同表述（姓名变体、昵称）
- 不同人物可能使用相同姓名（重名问题）
- 需要将同一人物的不同提及合并为唯一ID

**技术方案：基于搜索增强的LLM消歧系统**

**阶段一：特征提取与相似度计算**
```
1. 多维度特征提取
   - 基础特征：姓名、拼音、英文名
   - 上下文特征：公司、职位、行业、教育背景
   - 关系特征：共同联系人、合作项目
   - 时间特征：活动时间线、职业轨迹

2. 向量化表示
   - 使用BERT/RoBERTa生成人物描述向量
   - 使用图神经网络（GNN）生成关系网络向量
   - 多模态特征融合

3. 相似度计算
   - 余弦相似度、编辑距离
   - 基于图结构的相似度（共同邻居、路径相似度）
   - 基于时间序列的相似度（职业轨迹匹配）
```

**阶段二：搜索增强的LLM消歧**
```
1. 候选检索
   - 基于姓名和关键特征（公司、职位）检索候选人物
   - 使用向量数据库（Milvus/Weaviate）进行快速检索
   - 返回Top-K候选人物

2. LLM增强判断
   - 构建消歧Prompt，包含：
     * 待消歧人物信息（姓名、公司、职位、时间等）
     * 候选人物信息（每个候选的完整画像）
     * 相似度分数
   
   - LLM任务：
     * 判断是否为同一人（是/否/不确定）
     * 如果确定，给出置信度分数
     * 如果不确定，指出关键差异点

3. 决策融合
   - 结合向量相似度分数和LLM判断结果
   - 使用规则引擎处理边界情况
   - 人工审核高价值但低置信度的案例
```

**阶段三：迭代优化**
```
1. 反馈学习
   - 收集人工审核结果作为训练数据
   - 微调LLM模型，提高消歧准确率
   - 优化特征权重和相似度计算

2. 主动学习
   - 识别高价值但低置信度的消歧案例
   - 优先进行人工审核
   - 持续提升模型性能
```

#### 2.3.2 ID画像构建

**画像维度：**
1. **基础信息**
   - 姓名（标准名、别名、英文名）
   - 性别、年龄（推断）
   - 照片（如有）

2. **职业信息**
   - 当前职位：公司、职位、部门、时间
   - 历史职位：完整的职业轨迹
   - 行业标签：主要行业、细分领域

3. **教育背景**
   - 学历：学校、专业、学位、时间
   - 教育轨迹：从本科到最高学历

4. **投资关系**
   - 作为投资方：投资的公司、轮次、金额、时间
   - 作为被投方：获得投资的轮次、金额、投资方

5. **合作关系**
   - 合作伙伴：共同创业、合作项目
   - 社交网络：LinkedIn连接、共同参与的活动

6. **影响力指标**
   - 媒体报道频次
   - 社交媒体活跃度
   - 行业会议参与度
   - 专利/论文数量（如适用）

**画像更新机制：**
- 实时监控：新数据抓取后自动触发画像更新
- 增量更新：仅更新变化的部分，保持历史版本
- 置信度标记：对每个信息点标记数据来源和置信度

### 2.4 关系网络构建层

#### 2.4.1 关系类型定义
- **职业关系**: 同事、上下级、同行业
- **投资关系**: 投资方-被投方、共同投资
- **合作关系**: 联合创始人、合作伙伴
- **教育关系**: 校友、师生
- **社交关系**: LinkedIn连接、共同参与活动

#### 2.4.2 关系强度计算
- **直接关系强度**: 基于关系类型、持续时间、互动频次
- **间接关系强度**: 基于路径长度、共同联系人数量
- **关系时效性**: 考虑时间衰减，近期关系权重更高

#### 2.4.3 图数据库存储
- 使用Neo4j或ArangoDB存储人物节点和关系边
- 支持复杂图查询（最短路径、社区发现、影响力分析）
- 建立索引优化查询性能

## 三、商业化路径

### 3.1 产品形态

#### 3.1.1 数据API服务
- **人物查询API**: 根据姓名、公司等条件查询人物画像
- **关系查询API**: 查询两人之间的关系路径和强度
- **网络分析API**: 社区发现、影响力分析、关系推荐
- **实时更新API**: 订阅特定人物的信息更新

#### 3.1.2 SaaS平台
- **人物画像展示**: 可视化人物完整画像
- **关系网络可视化**: 交互式关系图谱
- **搜索与筛选**: 多维度搜索和筛选功能
- **数据导出**: 支持Excel、CSV、JSON等格式导出

#### 3.1.3 定制化数据服务
- **行业报告**: 特定行业的人物关系网络分析报告
- **投资研究**: 为投资机构提供标的公司关键人物关系分析
- **BD支持**: 为企业BD团队提供目标客户关键联系人分析

## 五、风险与挑战

### 5.1 技术风险

**人名消歧准确率：**
- **风险**：消歧准确率不足，影响数据质量
- **应对**：持续优化算法，建立人工审核机制，采用主动学习策略

**数据质量：**
- **风险**：数据源不稳定，数据质量参差不齐

### B. 竞品分析

**国内竞品：**
- 企查查、天眼查：主要关注企业信息，人物关系较弱
- 脉脉：社交网络，但数据不对外开放
- 36氪、虎嗅：媒体平台，缺乏结构化数据服务

**国外竞品：**
- Crunchbase：主要关注创业公司和投资关系
- LinkedIn：社交网络，数据不对外开放
- ZoomInfo：B2B数据服务，但主要面向海外市场

**差异化优势：**
- 专注于人物关系网络，而非企业信息
- 基于搜索增强LLM的消歧技术，数据质量更高
- 面向中国市场，数据覆盖更全面
